# ExamPrep — платформа методички и скриптов

Веб-приложение для подготовки к демонстрационному экзамену: публичные Markdown-статьи, полные версии по ключу, защищённые файлы скриптов и админ-панель для управления контентом и ключами.

## Что реализовано

- Публичный каталог статей и просмотр Markdown с подсветкой базового форматирования, таблицами, изображениями и кодовыми блоками.
- Отдельные публичная и полная версии каждой статьи.
- Активация ключа доступа; срок действия, максимальное число активаций и отзыв ключей.
- Скрипты хранятся вне публичного каталога. Пользователь с полным доступом видит готовую команду `wget <ссылка>`; ссылка содержит случайный секретный токен и заканчивается именем файла, поэтому `wget` сохраняет скрипт под обычным именем.
- Админ-панель: добавление, редактирование, публикация и удаление статей и скриптов; создание и отзыв ключей.
- Загрузка zip-архива с компьютера через админ-панель (вкладка «Архив»): `README.md` становится статьёй, `*.sh` — скриптами, `docs/images` — изображениями. Повторная загрузка обновляет существующие статью и скрипты.
- SQLite без ORM; данные и закрытые файлы сохраняются в bind mounts.

## Запуск через Docker Compose

1. Установи Docker Engine и Docker Compose plugin.
2. Создай `.env` из примера:

   ```bash
   cp .env.example .env
   ```

3. Установи собственные значения `ADMIN_PASSWORD` и `SESSION_SECRET` в `.env`. Для секрета можно сгенерировать значение командой:

   ```bash
   openssl rand -hex 32
   ```

4. Запусти приложение:

   ```bash
   docker compose up -d --build
   ```

5. При локальной проверке открой `http://127.0.0.1:8015`. Админ-панель: `/admin`.
6. Войди в админ-панель, открой вкладку «Архив» и загрузи zip-архив с материалами со своего компьютера (до 200 МБ). После импорта можно редактировать статьи и скрипты.

   Если сайт стоит за Nginx, подними лимит размера запроса, иначе загрузка архива больше 1 МБ вернёт ошибку 413:

   ```nginx
   client_max_body_size 200m;
   ```

В production сайт должен открываться через HTTPS reverse proxy. В Compose порт опубликован только на `127.0.0.1:8015`, чтобы его можно было подключить к существующему Nginx. Включён `COOKIE_HTTPS_ONLY=1`; для локального теста без HTTPS временно выставь `COOKIE_HTTPS_ONLY=0`.

## Безопасность и ограничения MVP

- Не используй стандартный пароль и не публикуй `.env`.
- Ключи доступа хранятся в БД в виде SHA-256-хеша. Полный ключ показывается только один раз после создания.
- Ключ ограничивает количество активаций, но после успешной активации доступ хранится в браузерной сессии до её окончания/удаления или нажатия «Закрыть доступ». Это не персональные аккаунты и не DRM: пользователь с полным доступом может сохранить или переслать полученные файлы.
- Ссылка на скрипт — секретная и постоянная: `wget` не передаёт cookie браузера, поэтому сессия при скачивании не проверяется, и файл получит любой, кто знает ссылку. Чтобы отозвать утёкшую ссылку, удали скрипт и добавь его заново — токен сменится.
- Перед публичным запуском добавь резервное копирование `data/` и `private/scripts/`, HTTPS, rate limiting на вход и активацию ключа, CSRF-защиту для административных форм и настройку логирования.
- Каждый архив даёт свою статью: её название — первый заголовок `#` в README, изображения копируются в `data/uploads/<slug статьи>/`. Скрипты сопоставляются по имени файла на весь сайт: `br-rtr.sh` из нового архива заменяет прежний, ссылка не меняется. Правки, сделанные через админку, при повторной загрузке того же архива перезаписываются.
- Приложение не исполняет загруженные скрипты. Оно только хранит их и отдаёт по секретной ссылке.

## Структура

```text
app/main.py          FastAPI-маршруты и SQLite
app/templates/       Jinja2-шаблоны
app/static/style.css стили интерфейса
data/                База данных и изображения
private/scripts/     Закрытые файлы скриптов
tests/               Самопроверка импорта архива
```
